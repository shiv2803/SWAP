## Brief Description & Limitations

**What the model does.** SWAP switches a wireless link between Wi-Fi, BLE and LoRa as radio
conditions change. The classifier is the decision layer: it consumes one live telemetry frame —
`wifi_rssi`, `wifi_loss`, `ble_rssi`, `lora_rssi`, `lora_snr`, `lora_loss`, `rtt_ms` — and outputs
which of the three protocols the link should be using. It runs on the UNO Q's Linux side, which
issues `force_protocol` commands back down the UART to the ESP32 node. Learned feature importance
is dominated by `rtt_ms` (0.33), `wifi_loss` (0.28) and `wifi_rssi` (0.19), which matches the
physical intuition that latency and Wi-Fi degradation are what should trigger a handover.

**Why a Random Forest.** The decision is low-dimensional (7 features, 3 classes) and must be
explainable and fast on a CPU-only Linux target. A depth-8 forest gives per-frame inference in
well under a millisecond with no accelerator, and its feature importances can be inspected
directly — which matters for a system whose job is to justify handover decisions.

### Limitations — stated plainly

1. **The 96% figure measures agreement with a heuristic, not real-world optimality.** Training
   labels are generated by `swap_backend.link_quality_model.compute_raw_scores()` — the project's
   own rule-based scoring function. The model is therefore learning to *imitate* that heuristic, so
   accuracy expresses fidelity to the rules, not proof that the chosen protocol was genuinely the
   best one. This was deliberate (it keeps the ML path and the rule-based fallback from drifting
   apart), but it is not the same as ground truth from measured link outcomes.

2. **Training data is simulator-generated, not measured RF.** The telemetry uses the real
   production schema, but the values come from the backend simulator rather than physical radio
   measurements. Validating and, if needed, retraining against real hardware telemetry is a planned
   and not-yet-completed step.

3. **Per-frame prediction, no temporal context.** The model classifies a single telemetry line in
   isolation, while the rule-based path reasons over a 10-sample rolling window. The model can
   therefore react to a one-frame outlier where the heuristic would smooth it out. Hysteresis to
   prevent handover flapping is handled outside the model, in the switching state machine.

4. **Class imbalance.** BLE accounts for 47% of samples versus Wi-Fi's 25%. This is mitigated with
   `class_weight="balanced"`, and Wi-Fi still reaches 0.99 recall, but the split reflects the
   simulator's conditions rather than a deliberately balanced experimental design.

5. **Wi-Fi precision is the weakest number (0.93).** The confusion matrix shows the residual error
   is almost entirely BLE↔Wi-Fi confusion (1,365 BLE frames predicted as Wi-Fi). LoRa is nearly
   never confused with either (precision 1.00) — unsurprising, since LoRa is selected under
   distinctly worse conditions than the other two.

6. **Not an on-MCU model.** Inference is Python on the UNO Q's Linux SoC. This is a Physical AI
   system in that the model closes a loop over real radio hardware, but the model itself is not
   embedded on the microcontroller.
